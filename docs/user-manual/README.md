# Arena user manual

The manual (Open Foris Arena Handbook), edited with Word or LibreOffice Writer, in three languages:

| Language | Source | PDF |
|---|---|---|
| English | `arena-user-manual.docx` | `arena-user-manual.pdf` |
| French | `arena-user-manual-fr.docx` | `arena-user-manual-fr.pdf` |
| Spanish | `arena-user-manual-es.docx` | `arena-user-manual-es.pdf` |

`scripts/` contains the build scripts.

## Links to the latest version

These links don't change over time: they always open the manual of the latest Arena release.

| Language | Release asset | GitHub Pages (opens in the browser) |
|---|---|---|
| English | <https://github.com/openforis/arena/releases/latest/download/arena-user-manual.pdf> | <https://openforis.github.io/arena/arena-user-manual.pdf> |
| French | <https://github.com/openforis/arena/releases/latest/download/arena-user-manual-fr.pdf> | <https://openforis.github.io/arena/arena-user-manual-fr.pdf> |
| Spanish | <https://github.com/openforis/arena/releases/latest/download/arena-user-manual-es.pdf> | <https://openforis.github.io/arena/arena-user-manual-es.pdf> |

The PDFs are generated by the [User manual workflow](../../.github/workflows/user-manual.yml):

- every published release gets them as assets and publishes them on GitHub Pages;
- every pull request changing the manual gets them as the `user-manual` artifact of the workflow run, to check the result;
- a manual run of the workflow (on `master`, with the tag of an existing release) attaches them to that release.

The PDFs committed here are the ones of the latest version of the `.docx` files (they may describe changes not released yet).

## Updating the manual

Update the manual in the same pull request as every user-facing change, in all three languages, and regenerate
the PDFs (`yarn docs:manual`) to commit them too.

- Keep the `{{version}}` and `{{releaseDate}}` placeholders on the cover: they are replaced with the version (from `package.json`) and the date when generating the PDF.
- The table of contents and the page numbers are updated when generating the PDF.
- Keep the documents in `.docx` format (in LibreOffice: **Keep current format** when saving).
- The PDFs are generated with LibreOffice: use fonts available on Linux or metric-compatible with them (Calibri and Cambria are replaced by Carlito and Caladea), and check the PDF artifact of the pull request.
- Add new sections at the end of the related chapter, so that the numbering of the existing ones does not change (section numbers are plain text).
- UI labels in bold, as they appear in the app in the language of the manual (see `core/i18n/resources/<lang>`).
- Screenshots: light theme, English UI (also in the French and Spanish manuals), realistic data (no test names), cropped to the part of the page being described; replace the ones that no longer match the UI.

To generate the PDFs locally (all languages, or only the given ones, e.g. `yarn docs:manual fr`):

```bash
yarn docs:manual
```

It requires [LibreOffice](https://www.libreoffice.org/) and node. If LibreOffice is not found, set the `SOFFICE` variable to the `soffice` executable. With a LibreOffice installed from the Linux distribution packages, `python3-uno` is also needed.

# Arena user manual

- `arena-user-manual.docx`: the manual (Open Foris Arena Handbook), edited with Word or LibreOffice Writer.
- `scripts/`: build scripts.

The `.pdf` is generated by the [User manual workflow](../../.github/workflows/user-manual.yml) and is not committed:

- every published release gets it as asset and publishes it on GitHub Pages: the latest version opens in the browser at <https://openforis.github.io/arena/arena-user-manual.pdf>;
- every pull request changing the manual gets it as the `user-manual` artifact of the workflow run, to check the result.

## Updating the manual

Update the manual in the same pull request as every user-facing change.

- Keep the `{{version}}` and `{{releaseDate}}` placeholders on the cover: they are replaced with the version (from `package.json`) and the date when generating the PDF.
- The table of contents and the page numbers are updated when generating the PDF.
- Keep the document in `.docx` format (in LibreOffice: **Keep current format** when saving).
- The PDF is generated with LibreOffice: use fonts available on Linux or metric-compatible with them (Calibri and Cambria are replaced by Carlito and Caladea), and check the PDF artifact of the pull request.
- Add new sections at the end of the related chapter, so that the numbering of the existing ones does not change (section numbers are plain text).
- UI labels in bold, as they appear in the English version of the app (see `core/i18n/resources/en`).
- Screenshots: light theme, English UI, realistic data (no test names), cropped to the part of the page being described; replace the ones that no longer match the UI.

To generate the PDF locally:

```bash
yarn docs:manual
```

It requires [LibreOffice](https://www.libreoffice.org/) and node. If LibreOffice is not found, set the `SOFFICE` variable to the `soffice` executable. With a LibreOffice installed from the Linux distribution packages, `python3-uno` is also needed.
